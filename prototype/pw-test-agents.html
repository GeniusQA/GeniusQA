三、需要后端提供的接口

  

    
接口通道说明

    
      
POST /ui/agents/initHTTP执行 init-agents --loop=，返回工作区结构

      
POST /ui/agents/planHTTP创建 Planner Job，直接复用 Skill Job 表

      
POST /ui/agents/generateHTTP创建 Generator Job，入参为选中的 spec + 场景

      
POST /ui/agents/healHTTP创建 Healer Job，入参为失败的 test 名

      
GET  /skills/.../jobs/{id}/streamSSE已存在，无需开发

      
GET  /ui/agents/artifactsHTTP列出 specs/ 与 tests/ 文件树

      
GET  /ui/agents/file?path=HTTP读文件内容（需做路径逃逸校验）

      
POST /ui/agents/adoptHTTPspec.ts → ui_test_cases，tags.spec_path 挂载（零 DDL）

    
  


  
四、与 agent-device 方案的关键差异

  

    
维度APP · agent-deviceWeb · Test Agents

    
      
交互节奏毫秒级，人在环内实时点选分钟级，人在环外审阅采纳

      
UI 形态设备操作台（实时投屏 + 元素树）任务流水线（阶段状态机 + 产物审阅）

      
后端载体需新建 MCP 常驻会话池直接复用 Skill Job，零新建

      
产物步骤数组 → app_scripts.script文件（.md / .spec.ts）→ 工作区 + tags.spec_path

      
人的角色操作者（点、填、断言）审阅者（改计划、采纳补丁）

      
必要改造会话池 + 操作台（重）流式日志（subprocess.run→Popen）
